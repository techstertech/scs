# SCS 0.4.0 release

## Approved outcome

Publish SCS 0.4.0 through its existing public GitHub release workflow. The user
selected a minor release for the external decision API configuration migration.
Preserve SCS configuration and indexes, Cortex, terminal sessions, and unrelated
services. No additional product or dependency changes are planned.

## Release contract

- Python metadata, Rust workspace/packages, runtime identity, lockfiles, tag,
  wheels, and installer identify version 0.4.0.
- Release notes explain the actual external model ID, model-qualified readiness,
  `routing.provider = external`, and deterministic routing when disabled.
- A service must support readiness for the configured model before clients
  migrate from the former model-specific selector. SCS runs no decision model.
- Published assets and tags are immutable. Corrections receive another version.
- No index format or production dependency changes are included. Existing
  configuration uses the external API contract and remains unchanged on install.

## Acceptance criteria and verification

1. All release identities agree and existing behavior passes required gates.
   Run the maintained version checker, version tests, and `just verify`.
2. The release commit reaches main and passes hosted macOS/Linux CI before
   tagging. Verify a signed annotated tag at that exact commit.
3. The release contains both supported wheels, source, exact constraints,
   installer, SPDX SBOM, and checksums. Download all seven assets, verify every
   payload checksum, and verify each asset's GitHub provenance against the tag,
   source commit, and maintained release workflow.
4. The public release explains the configuration and metadata migration and
   becomes the latest stable release.
5. The published macOS installer works outside the checkout and activates
   version 0.4.0. Run checkout-independent imports, doctor, and the existing
   fresh MCP smoke command. Verify configuration and original project identities
   remain unchanged and disposable fixtures are removed.
6. Hosted Linux wheel checks pass. Preserve Cortex and terminal runtime process
   identities during local activation.

Use existing tests and generated MCP fixtures. Add no tests for version metadata
or documentation edits. Record actual commands and outcomes before sign-off.

## Recovery and boundaries

Before local replacement, preserve the current executable environment and
configuration in a timestamped project folder on the verified external backup
volume. Verify checksums and configuration restoration. Restore that private
candidate backup if activation fails. The published 0.3.0 client requires its
older decision configuration; setting `decision_model = "disabled"` also permits
deterministic routing. No index restoration or migration is needed.

Use the supported installer and cooperative SCS shutdown. Never interrupt
Cortex, its terminal runtime, or unrelated services. Publish no MES release and
change no model-serving configuration.
