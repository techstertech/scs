# SCS 0.5.0 release and local upgrade

## Outcome and authorization

Publish the bundled-model feature as version 0.5.0 and upgrade the local SCS
installation through the verified release installer. The user explicitly
authorized both operations. The installed baseline is 0.4.0, not 0.4.1.

The release adds local Qwen embeddings, Qwen reranking, and English Laya for
fresh supported Macs. Existing external settings retain their behavior. The
[model spec](2026-11-14-bundled-local-models.md) defines those contracts and
records the source implementation evidence.

## Scope and boundaries

Synchronize version sources, lockfiles, changelog, and current installation
guidance. Use the maintained GitHub main CI and release workflow. Verify
immutable public assets before upgrading through the supported installer.
No model settings, repository source outside this checkout, protocol, or stored
schema changes are included. Preserve all enrolled projects and credentials.

The local daemon has 23 enrolled projects and no observed active indexing job.
Retain configuration and catalog identity proofs privately. Recheck active work
before replacement. Use cooperative shutdown; do not terminate unrelated
services, Cortex, its terminal runtime, or external model services.

## Acceptance criteria

1. Python, Rust, runtime, installer, tag, and assets identify 0.5.0. Version
   validation, local verification, and hosted macOS/Linux CI pass.
2. The maintained release workflow publishes both wheels, source, constraints,
   installer, SBOM, and checksums. Downloaded bytes and build attestations verify
   against the release tag and source commit.
3. A disposable installation of the public macOS wheel performs local model
   indexing and queries, then works after a fresh restart with IP access denied.
4. The supported installer replaces the local tool safely. Its runtime and
   daemon report 0.5.0. A fresh MCP session and doctor report readiness.
5. Configuration bytes and permissions, existing provider choices, project IDs,
   roots, store IDs, and active generations match the pre-upgrade baseline.
   Existing configured external inference works after replacement.
6. Temporary validation state is removed. Retained evidence identifies executed
   checks and material limitations. The checkout is committed and clean.

## Verification and recovery

Run the version checker, targeted release tests, `just verify`, model-tool checks,
and documentation links before publishing. Require green main CI before pushing
the signed annotated tag. Verify release checksums and GitHub provenance, then
test the public installation before replacing the global tool.

If activation fails, reinstall the verified 0.4.0 release through the supported
installer. Both releases retain the existing external provider and data formats.
No project deletion, forced reindex, or database mutation is part of rollback.

Physical 16 GB testing remains unavailable. Do not describe that hardware target
as qualified. Hosted Linux execution is a release gate; older-macOS execution
remains unverified. These limits stay explicit in the release documentation.

## Verification limits and findings

The disposable public installation starts with an empty fixture index. Its model
cache was populated before publication through the pinned `ModelCache` verifier.
The public-release checks prove verified-cache use, indexing, and offline restart.
They do not prove an automatic download into an empty public-installation cache.
The [source implementation evidence](../evals/reports/2026-11-14-bundled-local-models/README.md)
retains the separate cold-download proof.

An initial external review attempt records `classifier_timeout` at the unchanged
0.5-second deadline. Warmed 0.4.0 and public 0.5.0 installations each pass all ten
review checks. The installed global 0.5.0 release also passes all ten checks.
The external provider class AST, selection instructions, and query orchestrator
are identical. The initial timeout remains part of the evidence.

One historical embedding connection failure predates replacement. A later full
reconciliation of the same repository completes successfully. No outstanding job
remains. Four historical source directories are absent. Their stored graphs
remain ready, while source-reading MCP tools retain their existing path guard.

Existing MCP connections can retain a closed connection after daemon replacement.
Reconnect those clients. Fresh global MCP sessions pass; an already connected
session is not evidence of the replacement daemon's health.

Physical 16 GB and older-macOS execution remain unverified. Hosted Linux CI passes.
These limitations do not establish hardware performance beyond the tested host.
