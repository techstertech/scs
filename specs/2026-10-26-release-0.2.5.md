# SCS 0.2.5 release

## Approved outcome and scope

The user approved publication of the nested-repository fix and local SCS upgrade.
Publish 0.2.5 through the existing GitHub Releases process, then install its
verified public macOS wheel. No dependency, MCP schema, or data format changes.
TSG remains pinned at 0.2.4. Nested Git repositories require separate explicit
ingestion; normal folders remain traversable and directory cycles are avoided.

## Acceptance criteria

1. Python, Rust, runtime, tag, wheel, and installer identities agree on 0.2.5.
2. Local required checks and hosted macOS/Linux CI pass before tagging.
3. Both wheels, source, constraints, installer, SBOM, and checksum manifest are
   published; their checksums and exact-workflow provenance verify.
4. The installed public wheel reports 0.2.5, reaches readiness, and exposes the
   expected MCP inventory while preserving current settings and registrations.
5. Installed-wheel fixtures exclude nested files from parent discovery, allow
   explicit child ingestion, and stop traversal at Git boundaries.

## Verification plan

Run the version checker, lockfile compatibility check, and `just verify`.
Require hosted CI and every release job. Download assets, check SHA-256 values,
and verify provenance against the exact commit, tag, and release workflow.
Run the supported public installer and smoke tests outside the checkout.
Compare configuration digest and project registrations before and after.
Keep Cortex running. Do not reindex existing user repositories automatically.

## Recovery and limitations

Published assets are immutable. Corrections require another version. Reinstall
0.2.4 for executable rollback; it lacks nested-repository isolation. No index
reset or configuration change is needed. Existing parents require reconciliation
to remove previously indexed nested files; that is outside this release task.

## Verification results

Release preparation passed `RUSTUP_TOOLCHAIN=1.98 just verify`: 453 Python
tests, 108 Rust tests, 87.42% coverage, strict typing, and lint.
`python3 scripts/check-release-version.py v0.2.5` passed. The lockfile passed
`uvx --from uv==0.12.9 uv lock --check --offline`, matching hosted CI.
Only first-party package versions changed; TSG remains pinned at 0.2.4.
All five acceptance criteria passed.

- Criterion 1: the identity checker passed. The signed annotated `v0.2.5` tag
  resolves to `4d2b2f8d78ec90ace335f2bdd6afcc890a6631f8` on main;
  `git verify-tag v0.2.5` passed.
- Criterion 2: [main CI](https://github.com/techstertech/scs/actions/runs/40346050111)
  passed macOS, Linux, and the supply-chain audit. Every job in the
  [release workflow](https://github.com/techstertech/scs/actions/runs/40347502757)
  passed, including both independent wheel installation and linkage checks.
- Criterion 3: the stable [0.2.5 release](https://github.com/techstertech/scs/releases/tag/v0.2.5)
  contains seven assets. `shasum -a 256 -c SHA256SUMS` verified six payloads.
  `gh attestation verify` passed for all seven assets, enforcing exact source
  digest, tag ref, repository, expected workflow, and hosted runners only.
- Criterion 4: the supported checksum-verified installer upgraded local SCS
  from 0.2.4 to 0.2.5. `scs version` returned 0.2.5; `scs doctor` reached
  readiness. Outside the checkout, with `PYTHONPATH` removed, the installed
  wheel initialized its stdio MCP bridge and exposed the exact five tools.
  Configuration SHA-256 and all project IDs/roots remained unchanged.
- Criterion 5: an installed-wheel fixture traversed a normal source folder,
  excluded a nested Git root, handled a directory-symlink cycle, rejected
  parent-scoped individual-file ingestion, and accepted child-scoped ingestion.
  A real native graph persisted disjoint parent and child file sets.

The registered project's file count rose from 960 to 1735 during the release

passed. Its last-indexed timestamp (15:27:29 UTC) predates public-wheel
installation (15:30:30 UTC), so the count change was not caused by the upgrade.
No existing user repository was explicitly reindexed by this release task.

No plan deviations or data migrations occurred. Linux installation was checked
